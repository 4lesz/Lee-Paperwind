## 4. 双击打开的手动步骤（AC-D02 / D03，已于 2026-11-24 补验通过）

测试文件在 `test-output/手动验收/`（甲.md、乙.md、丙.md）。2026-11-24 产品负责人按下列步骤操作，结果全部通过（见 §6）。

1. **AC-D02**：右键 `甲.md` →「打开方式」→「选择其他应用」→ 选 Paperwind 并勾「始终使用此应用」→ 关掉 Paperwind 后双击 `甲.md`，应直接用 Paperwind 打开。（以后想改回 Obsidian，同样操作选 Obsidian。）
2. **AC-D03**：① 关掉所有 Paperwind，从桌面图标打开（空白窗口），双击 `乙.md` → 在这个窗口打开；② 再双击 `丙.md` → 新开一个窗口；③ 再双击 `乙.md` → 不新开窗口，乙的窗口到最前。
3. （P1，可选）**AC-V08**：「设置 → 个性化 → 颜色」关掉「透明效果」，看标题栏和侧栏是纯色、字清楚；看完再打开。2026-11-24 产品负责人试过，肉眼无差异，按系统负责放行（§6）。

## 5. 已知问题（随 v0.1 发布，不影响门槛）

| 事项 | 影响 | 计划 |
|------|------|------|
| 1MB 级、含大量表格 / 代码块的文档里打字约 90ms/键 | 快速连打会有积压；600KB 以内无感 | 产品负责人决定暂不做「屏幕外不排版」，遇到再评估 |
| 链接跳转动效在大窗口、高分屏下掉帧 | 聚拢阶段偶有长帧 | 产品负责人决定先不处理 |
| 安装包约 117MB，没有代码签名 | 下载较大；安装时 Windows 提示「未知发布者」 | 签名需要证书，后续版本再定 |
| HTML 块在所见即所得模式下只读；`<details>` 只在顶层生效 | 编辑 HTML 要切源码模式 | 后续版本 |
| 改动过的块会被规范化（如 `*` 列表 → `-`） | 只影响改过的那一段，符合 AC-M04 | — |
| 窗口很窄时侧栏仍占 260px；没有「新建下一篇」、最近文件 | 功能范围 | 后续版本（PRD §8） |
| AC-E08（添加链接）在 M3 的 5 轮完整自测里失败过 1 次，原因未查明 | 之后各轮都通过；自测已加现场记录 | 再出现时按记录查 |
| 从 beta.2 升级时，beta.2 自带的卸载程序会整键删除 `Markdown`（可能是 Obsidian 的关联） | 只影响装过 beta.2 又装了 Obsidian 的试用者 | 发 beta.5 给试用者时提醒：`.md` 双击异常就在「打开方式」里重选一次 |

## 6. 发布决定（2026-11-06）

- 产品负责人看过本汇总后要求「打标签」；确认 AC-D02、AC-D03 没有手动试过后，决定**不等这两项，直接发布**。按 §9 门槛第 1 条这两项不算通过，记为**未验证**；已有的部分证据：「打开方式」里有 Paperwind（D02 前半），已打开的文件再打开一次不新开窗口（D03 三种情况之一）。之后补验，结果补进本节。
- 版本号 `0.1.0-beta.5` → `0.1.0`，代码不变，重新打包为 `release/Paperwind-Setup-0.1.0.exe`，提交后打标签 `v0.1.0`。
- **2026-11-24 补验（AC-D02 / D03）**：产品负责人按 §4 手动操作，三项全部通过——① 把 `.md` 默认应用设为 Paperwind 后，关闭程序双击 `甲.md` 直接用 Paperwind 打开；② 程序未运行、从桌面图标打开空白窗口后双击 `乙.md`，在现有窗口打开；③ 再双击 `丙.md` 新开窗口，再双击 `乙.md` 不新开窗口、聚焦到乙的窗口。`.md` 的默认打开方式现为 Paperwind（由产品负责人自己设置，不是安装包改的，AC-D07 不受影响）。至此 **P0 89 / 89 全部通过**。
- **2026-11-24 AC-V08 系统侧**：产品负责人关闭「透明效果」后实测肉眼无差异。半透明是向 Windows 请求的 Mica，关掉后由系统自行换成实色，程序侧没有第二套代码；只有 52px 标题栏和 260px 侧栏受影响，壁纸对比度低时几乎看不出变化。按「系统负责」放行，不记为不通过。
