## 4. 本轮测试脚本修正（AC-Q07 / AC-F15）

两条都是**自测脚本判定逻辑的问题，不是功能缺陷**；功能表现与验收标准一致，只修正了断言与时序。

### 4.1 AC-Q07 — 跨格式匹配的断言口径不对

**现象**：首轮自测 133 / 134，唯一失败项 AC-Q07（其余项与功能相关的计数、高亮、跳转全部正确）。

**原因**：`要的 要` 在文档里是「重**要**的 **要**点」，命中区间跨过加粗的 mark 边界。ProseMirror 的 `Decoration.inline` 在 mark 边界处会被拆成多个 DOM 片段，所以这一处匹配渲染成了 **3 个** `.find-hit` 元素。原断言按「`.find-hit` 段数 = 匹配处数」判断，得到 `hits = 3`，与期望的 1 不符 —— 实际匹配位置、计数 `1/1`、当前匹配加重都正确。

**修正**（[selftest.cjs](file:///d:/markdown_app/scripts/selftest.cjs#L650-L669)）：不再数段数，改为两条等价且更稳的断言：

1. 所有 `.find-hit` 的文字按文档顺序拼起来，必须**正好等于**查询词 `要的 要`（证明命中的是同一处、没有多算也没有少算）；
2. `.find-hit:not(.find-current)` 数量为 0（证明这一处整体被标为当前匹配，没有残留的「非当前」高亮）。

计数仍要求 `1/1`，与验收标准 §8g 的描述一致。

**通过后的证据**：

```
{"needle":"1/2","needleHits":2,"跨格式":"1/1",
 "跨格式片段":{"text":"要的 要","notCurrent":0},
 "跨段":"无结果","标记":"无结果","apple":"1/2"}
```

### 4.2 AC-F15 — 草稿提示条是异步出现的，脚本点得太早

**现象**：AC-Q07 修好后的一轮里，AC-F15 偶发失败（「丢弃后不再出现」判定为假），且不是每轮都复现。该检查属于 v0.1 回归范围，与查找替换无关。

**原因**：打开文件后，渲染层要先向主进程读取草稿，拿到内容后才插入草稿提示条。原脚本 `loadFile` 固定等 400ms 就调用 `document.querySelector('.draft-banner [data-a=drop]')?.click()`；机器稍慢时提示条还没渲染出来，`?.` 让点击**静默跳过**，草稿没被清理，于是后面重新打开时提示条再次出现，判定失败。

**修正**（[selftest.cjs](file:///d:/markdown_app/scripts/selftest.cjs#L962-L986)）：把「点得早」和「判得早」都换掉。

1. 点之前先轮询，最多等 1.5 秒，确认 `.draft-banner` 已出现；仍没出现则直接判失败（不再静默跳过）；
2. 点击「丢弃」后，重新打开同一文件，再轮询约 1.8 秒：这段时间里只要提示条冒出来就判失败，全程没有才算通过。

**通过后的证据**：

```
{"draftFiles":4,"banner":true,
 "text":"发现 2026/11/24 16:41:43 未保存的草稿丢弃恢复",
 "restored":true,"dirty":true,
 "file":"...\\test-output\\tmp\\草稿测试.md","noBannerAfterDrop":true}
```

### 4.3 临时目录清理（附带）

Windows 上刚被进程放开的文件偶尔删不掉（`ENOTEMPTY`），曾让一轮自测在开头中断。`tmp` 目录删除改为重试 3 次、每次间隔 300ms。与查找替换功能无关。
