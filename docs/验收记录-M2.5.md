## 8. 试用反馈：GitHub 风格文档（2026-11-05，规范 v1.4）

产品负责人试用时打开了一份 GitHub 项目的 README（`awesome-agentic-ai-zh/README.zh-Hans.md`），反馈「显示不正常，排版也很奇怪」。排查后发现问题分两类，产品负责人确认两类都修。

### 8.1 发现的问题

| # | 问题 | 类别 | 根因 |
|---|------|------|------|
| 1 | 带文件夹的相对链接（`stages/01.md`）显示为普通文字，**保存后链接被删除** | 损坏文件 | 编辑器组件自带的链接安全检查有缺陷：正则里的 `.-:` 被当成字符范围，把 `/` 也排除了，所有含 `/` 的相对路径都被判为不安全 |
| 2 | 图片后紧跟的标题，保存后与图片挤成一行，标题失效 | 损坏文件 | 图片是块级元素，但序列化时按行内写出，后面没有空行 |
| 3 | 带链接的徽章 `[![x](图)](链接)` 保存后丢掉链接 | 损坏文件 | 块级图片不能带链接格式 |
| 4 | 链接、图片地址里的中文保存后变成 `%E8%AA%9E…` | 改写文件 | markdown-it 解析时对地址做了百分号编码 |
| 5 | `<a name>` 锚点、`<br>`、列表空行、表格分隔行等在保存时被改写或删除 | 改写文件 | 「解析 → 重新生成」这一来一回必然改写写法 |
| 6 | HTML 显示为灰色代码块，包裹标签各占一大块 | 显示 | M2 的设计是「HTML 原样保留、显示为代码」 |
| 7 | 徽章一个一行、间距很大 | 显示 | 同 #3 |
| 8 | 滚动时正文从格式栏上方露出、被标题栏切掉半行 | 显示 | 格式栏后方没有底衬 |

**影响面**：用这份 README 所在的仓库（268 个 Markdown 文件，只读）做往返测试，修复前 **257 个**文件「打开 → 不改 → 保存」后内容会变化；我们自己的样本中 `连载/01-开篇.md`、`02-第二章.md` 的中文链接也会被改成编码形式。产品负责人的原文件没有被保存过，未造成实际损失。

### 8.2 修复

| 修复 | 说明 |
|------|------|
| **原文保留**（新增 `src/source-preserve.js`） | 载入时记下每个顶层块的原文；保存时内容没变的块直接写回原文，只有改动过的块才重新生成；相邻两块都没改时，中间的空行和引用定义也按原文保留。这是治本的改法：以后遇到新的写法差异，只要没改那一段，文件就不会变 |
| 链接安全检查 | 换成自己的检查（`src/paths.js`）：相对路径、`#标题`、Windows 路径、http(s)、mailto 等允许；`javascript:` 等其他协议拒绝 |
| 地址保持原文 | 不再做百分号编码；含空格时写成 `<地址>` |
| 链接写法 | 记住原来是裸网址、`<网址>` 还是 `[文字](地址)`，重新生成时照原样写 |
| 图片改为行内元素 | 可以和文字、其他图片同处一段，可以带链接；插入图片时，光标在空段落或标题中则单独成段 |
| `<br>`、`<a name>` | `<br>` 保存时仍写 `<br>`；没有 href 的 `<a>` 作为 HTML 保留 |
| HTML 直接渲染（§5.1） | 白名单过滤后渲染；包裹标签、注释在编辑模式为小标签、阅读模式隐藏；`<div align>` 对齐生效；`<details>` 阅读模式可折叠；只含标签的段落阅读时不占行 |
| 格式栏底衬（§4.2） | 纸面同色，下沿 12px 渐隐 |
| 其他 | 文档以 HTML 块开头时不再自动选中它（阅读模式也不显示选中框）；本地图片不存在时返回 404 而不是在主进程报错 |

## 10. 试用反馈：整体圆角加大（2026-11-05，规范 v1.4）

产品负责人反馈「整体的设计风格还是不够圆润，比如翻页按钮的圆角可以再大一些」。给出两套方案并排对比后，选定**方案 A · 圆润**（方案 B 把卡片、条目、输入框做成胶囊形，未选）。

| 设计变量 | 原值 | 新值 | 主要用途 |
|----------|------|------|----------|
| `--r-xs` | 4px | **6px** | 行内代码、高亮、HTML 小标签 |
| `--r-sm` | 8px | **12px** | 按钮、侧栏条目、下拉选项 |
| `--r-md` | 12px | **16px** | 输入框、代码块、图片、表格、提示条、纸面左上角 |

## 11. 试用反馈：翻页动效（2026-11-05，规范 v1.4）

产品负责人觉得「翻页有点生硬」。先给出三种动效的可点击演示（方向滑入、淡入淡出、上浮淡入），产品负责人提出自己的方案：**旧页面内容呈粒子消散，新的一页按方向滑入**。已写入设计规范 §6.6，并新增设计变量 `--glide`。

### 11.1 做法

- 翻页前由主进程截取正文区域的**真实像素**（新增 `capture-rect` 接口，按页面缩放换算坐标），铺在一块画布上把画面定格；新的一篇在画布下面换好。
- 截图切成约 3px 的小方块，**只取有内容的地方**（和纸面底色相近的跳过），每颗保留原来的颜色；格式栏和底部翻页卡片所在区域不产生粒子。
- 粒子从离开的一侧逐列扫过（220ms + 0–100ms 随机），朝离开方向飘出 40–140px、略微上扬并淡出，单颗寿命 380ms；新页在 120ms 后从另一侧 32px 处滑入，420ms，`--glide`。
- 方向按篇目顺序：往后翻新页从右侧进入、粒子向左飘；往前翻相反。打开文件、打开文件夹、跨文件夹跳转不播放。
- 连续快速翻页：截图期间把「正在前往的那一篇」记为起点，下一次按键从它算起，不会把几次按键合并成一次；上一段动效立即结束。
- 系统开启「减少动态效果」时不截图、不产生粒子，只淡入 150ms。
- 新模块 `src/page-turn.js`；`src/main.js` 的 `gotoFile` 统一经过它，所以篇目、上一篇 / 下一篇、`Ctrl+[` / `Ctrl+]`、文中链接都有同样的动效。
